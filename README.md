# 秘仪室 · COC 在线房间平台

一个面向 COC 跑团的轻量在线舞台。KP 创建房间并控制场景、NPC 和玩家手卡；PL 通过独立链接进入同一房间，只会看到实时舞台，不会看到 KP 控制栏、备注或房主密钥。

当前内置《雾中献血车》前置模组及其场景、NPC、手卡与带团文档。

## 已实现

- 平台首页：KP 创建房间，PL 输入 6 位房间号加入。
- KP 控制台：切换地点、NPC、玩家手卡和在场玩家。
- KP 自定义图片：可为地点背景、NPC、素材和玩家席位上传替换图，并一键恢复默认图。
- KP 编辑模式：可修改房间标题、公开提示语、地点/NPC/素材/席位文本，并实时同步给玩家端。
- PL 只读舞台：不显示任何 KP 控件或备注。
- 实时同步：KP 操作后，同房间玩家通过 SSE 立即收到最新舞台状态。
- 房主权限：只有持有随机房主密钥的 KP 链接可以写入房间状态。
- 模板能力：支持默认模组、空白房间、导出模板文件、从模板文件创建房间。
- 零运行时依赖：房间服务使用 Node.js 内置模块。

## 本地运行

需要 Node.js 18 或更新版本：

```bash
npm start
```

然后打开：

```text
http://localhost:8791
```

也可以指定端口：

```bash
PORT=9000 npm start
```

## 使用流程

1. KP 在首页选择默认模组、空白房间，或导入模板文件创建房间。
2. KP 点击控制台顶部的“复制玩家链接”，发给玩家。
3. 玩家打开链接后进入只读舞台。
4. KP 切换地点、NPC 或玩家手卡，玩家端自动同步。
5. KP 也可以直接在控制台各卡片下点击“换图”，上传自己的背景图、人物图或线索图。
6. 如果希望复用当前配置，可在 KP 页导出 `.template.json` 文件，之后回到首页重新导入开房。

KP 链接中的 `key` 是房主密钥，请勿把完整 KP 链接发给玩家。应只分享 `/player/?room=房间号` 形式的玩家链接。

## 部署

实时房间依赖 Node.js 服务，不能只部署为 GitHub Pages 静态网站。仓库已包含 `Dockerfile`，可部署到任何支持 Node.js 或 Docker 的服务；启动命令为：

```text
npm start
```

服务会读取平台提供的 `PORT` 环境变量。当前房间状态保存在服务内存中，服务重启后房间会失效，且房间在 12 小时无活动后自动清理。正式长期运营时建议把房间状态迁移到 Redis 或数据库，并使用共享消息通道支持多实例部署。

上传的自定义图片也保存在当前 Node.js 进程内存里，因此同样会在服务重启后失效。

## 后续扩展

房间状态与实时事件接口已经分离，下一阶段可以继续增加：

- 房间内文字聊天、系统消息与投骰记录。
- 基于 WebRTC 的语音房间，服务端只负责信令和成员状态。
- 昵称、头像、在线成员列表与断线重连。
- Redis/数据库持久化、房间密码、主持人交接与权限管理。

## 项目结构

```text
src/pages/home/           React 首页入口
src/pages/kp/             React KP 控制台
src/pages/player/         React 玩家只读舞台
src/shared/               共享类型、API、房间状态与模板逻辑
server.mjs                静态资源、房间 API 与实时事件服务
kp-site/                  兼容保留的旧 KP 静态资源与样式
player/                   兼容保留的旧玩家静态入口
assets/                   模组图片素材
docs/                     模组正文与带团素材包
scripts/smoke.mjs         本地联调 smoke test
```

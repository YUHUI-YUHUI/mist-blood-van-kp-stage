# 秘仪室舞台编辑器改造任务文档

## 1. 背景

当前项目已经具备以下能力：

- KP 创建房间并控制当前展示的地点、NPC、素材、玩家席位
- 玩家通过独立链接进入只读舞台
- 房间状态通过 SSE 实时同步
- KP 可以为背景、NPC、素材、玩家席位上传自定义图片

但当前内容结构仍然偏“固定模组展示页”：

- 场景、NPC、素材的大部分文本内容仍写死在前端
- KP 可以换图，但不能系统化地改标题、描述、读白和提示语
- 团中控制与开团前编辑混在同一个界面语义里
- 项目本质上已经接近“实时跑团舞台编辑器”，但界面和数据结构还没有完全转过去

## 2. 项目目标

将当前网页从“固定模组控制台”升级为“可定制的实时跑团舞台编辑器”。

目标不是只服务《雾中献血车》一个模组，而是让 KP 能够：

- 快速创建一个房间并开团
- 在房间内替换图片和文本，改造成自己的团本舞台
- 在团中快速切换当前展示内容
- 让玩家端始终保持沉浸、简洁、只读

## 3. 核心设计原则

### 3.1 先演出，后配置

KP 在跑团时最重要的是“快切换、少误触”，不是“现场改数据”。

因此界面应区分：

- 演出模式：用于团中切换展示内容
- 编辑模式：用于开团前维护文本、图片和内容结构

### 3.2 玩家端只展示公开信息

玩家端只展示当前需要让玩家看到的内容，不出现：

- KP 备注
- 幕后目标
- 场景要点
- 房主密钥
- 编辑入口

### 3.3 图片与文本都属于房间数据

只做图片可编辑是不够的。对于这个项目来说，以下都应该属于可配置数据：

- 标题
- 副标题
- 场景名称
- 氛围短句
- NPC 名称与身份
- 线索名称与说明
- 玩家席位文案
- 玩家端可见提示语

### 3.4 模板和房间覆盖分离

默认模组内容应作为模板存在，房间中的自定义修改作为覆盖层存在。

这样可以同时满足：

- 保留默认模组素材
- 每个房间自由定制
- 后续支持“从模板创建房间”
- 后续支持“把当前房间存成新模板”

## 4. 用户与场景

### 4.1 KP

主要任务：

- 创建房间
- 准备自己的舞台内容
- 团中切换当前展示内容
- 控制玩家看到什么

痛点：

- 团中不希望大量表单干扰操作
- 开团前又需要完整编辑能力

### 4.2 玩家

主要任务：

- 进入房间
- 查看当前场景、人物、线索、在场玩家

关注点：

- 画面是否沉浸
- 信息是否清楚
- 是否不会看到后台信息

## 5. 目标产品形态

### 5.1 首页定位

首页应只承担“进入工作流”的职责，而不是承载复杂说明。

首页建议保留以下入口：

- 创建房间
- 加入房间
- 从模板创建
- 创建空白房间

### 5.2 KP 页三层结构

KP 页应由三个层级组成：

- 舞台：当前玩家实际看到的画面
- 控制：团中快速切换当前展示内容
- 编辑：修改当前房间的文本、图片与内容结构

### 5.3 KP 页两个主模式

#### 演出模式

适用于跑团进行中，只保留高频切换行为：

- 切换地点
- 切换 NPC
- 切换素材
- 切换在场玩家
- 显示或隐藏 KP 备注
- 重置当前舞台

#### 编辑模式

适用于开团前准备：

- 编辑房间标题和副标题
- 编辑场景字段
- 编辑 NPC 字段
- 编辑素材字段
- 编辑玩家席位字段
- 上传或恢复默认图片
- 调整内容顺序

## 6. 信息架构

### 6.1 KP 页结构建议

- 左侧：内容列表
- 中间：当前舞台预览
- 右侧：当前选中项编辑面板

#### 左侧列表

包含：

- 场景列表
- NPC 列表
- 素材列表
- 玩家席位列表

#### 中间舞台

用于实时预览玩家视角：

- 背景图
- NPC 立绘
- 素材图
- 在场玩家
- 玩家可见文字

#### 右侧编辑面板

根据选中内容动态切换表单：

- 选中场景时显示场景编辑表单
- 选中 NPC 时显示 NPC 编辑表单
- 选中素材时显示素材编辑表单
- 选中玩家时显示玩家席位编辑表单

## 7. 可编辑内容范围

### 7.1 房间级

建议支持：

- 房间标题
- 房间副标题
- 玩家端顶部提示语
- 默认房间封面图（可选）

### 7.2 场景级

建议支持：

- 场景名称
- 场景时间
- 场景氛围短句
- 场景背景图
- 场景目标（KP 可见）
- 场景读白（KP 可见）
- 场景要点列表（KP 可见）
- 场景公开说明（玩家可见，可选）

### 7.3 NPC 级

建议支持：

- NPC 名称
- NPC 身份/角色
- NPC 简介
- NPC 立绘
- NPC 备注
- NPC 玩家可见描述（可选）

### 7.4 素材级

建议支持：

- 素材名称
- 素材类型标签
- 素材说明
- 素材图片
- 触发时机备注

### 7.5 玩家席位级

建议支持：

- 席位名称
- 席位身份描述
- 席位头像/立绘
- 席位备注

## 8. 可见性分层

必须明确区分 KP 可见和玩家可见字段。

### 8.1 仅 KP 可见

- 场景目标
- 场景读白
- 场景要点
- NPC 备注
- 素材触发时机
- 房主密钥
- 所有编辑入口

### 8.2 玩家可见

- 当前背景图
- 当前 NPC 图像与公开名称
- 当前素材图像与公开标题
- 当前在场玩家
- 场景标题
- 简短公开描述
- 房间连接状态

## 9. 数据结构改造建议

当前写死数据应逐步改造成“模板 + 房间覆盖”。

建议房间状态至少包括：

```json
{
  "roomMeta": {
    "title": "秘仪室",
    "subtitle": "玩家可见副标题"
  },
  "stage": {
    "locationId": "campus",
    "npcId": "amy",
    "materialId": "blood-drive-flyer",
    "playerIds": ["p1"]
  },
  "customImages": {
    "locations": {},
    "npcs": {},
    "materials": {},
    "players": {}
  },
  "customText": {
    "locations": {},
    "npcs": {},
    "materials": {},
    "players": {},
    "roomMeta": {}
  }
}
```

后续可以再拆成：

- `templates`
- `roomOverrides`
- `runtimeStageState`

## 10. 实施阶段

### 阶段 1：文本可编辑基础能力

目标：

- 将主要文本从前端写死迁移到房间数据
- 先支持修改，不先做复杂模板管理

范围：

- 房间标题/副标题
- 场景名称、时间、氛围
- NPC 名称、身份、简介
- 素材名称、说明
- 玩家席位名称、描述

### 阶段 2：KP 编辑模式

目标：

- 增加独立编辑视图
- 将“团中控制”和“开团前配置”分开

范围：

- 模式切换
- 右侧编辑表单
- 保存与回退机制

### 阶段 3：玩家端文本联动

目标：

- 玩家端不只跟随图片，也跟随可公开文本变化

范围：

- 场景标题
- NPC 公开名称
- 素材标题
- 房间提示语

### 阶段 4：模板化

目标：

- 从固定模组升级为真正可复用的平台

范围：

- 从模板创建房间
- 空白房间
- 保存当前房间为模板

## 11. 验收标准

完成第一阶段后，应满足以下条件：

- KP 能修改主要文本，不需要改代码
- KP 修改后，房间内玩家端能实时看到应公开的变更
- KP 备注和幕后文本不会泄露到玩家端
- 现有图片上传能力仍正常工作
- 默认模组内容在未编辑时仍可正常使用

## 12. 非目标

本轮不优先处理：

- 多人协同编辑
- 模板市场
- 富文本排版系统
- 复杂权限系统
- 持久化存储方案重构
- 完整移动端编辑器优化

## 13. 后续建议

实现顺序建议为：

1. 先做文本可编辑数据层
2. 再做 KP 编辑模式
3. 再做玩家端公开文本联动
4. 最后做模板体系

这样能避免一开始就把界面做复杂，同时保证每一步都能产生可见价值。
